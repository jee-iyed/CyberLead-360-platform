# Database design

SQLAlchemy 2.x declarative models live in `src/cyberlead360/database/models.py`. The schema
is created and changed only through Alembic migrations in `alembic/versions/`.

## Tables
| Table | Purpose | Key constraints |
|---|---|---|
| `companies` | Target accounts | PK; **UNIQUE `normalized_domain`** (NULLs allowed); CHECK stage / qualification enum values; CHECK `employee_count > 0`; self-FK `merged_into_id` (SET NULL); index (stage, archived_at) |
| `contacts` | Professional contacts (personal data) | FK company (CASCADE); UNIQUE (company_id, professional_email); FK source (SET NULL); CHECK status/objection enums |
| `company_sources` | Where information came from | FK company (CASCADE); CHECK source type & verification enums; `collected_at`, `published_at`, `content_sha256` |
| `company_facts` | Atomic, sourced statements | FK company (CASCADE); **FK source NOT NULL, RESTRICT** (no fact without a source); CHECK type/confidence/review enums |
| `scoring_rules` | Versioned JSON configurations | UNIQUE `version`; `is_active` flag |
| `scoring_results` | Score history with breakdown | FK company (CASCADE); FK rule (RESTRICT); CHECK 0–100; index (company_id, is_current) |
| `outreach_drafts` | Generated/edited messages | FK company (CASCADE), FK contact (CASCADE); CHECK status & mode |
| `activities` | Interactions and stage changes | FK company (CASCADE), contact/opportunity (SET NULL); indexes on (company, occurred_at) and (follow_up_at, done) |
| `opportunities` | Deals | FK company (CASCADE); CHECK stage enum, `estimated_value >= 0`, probability 0–100 |
| `meetings` | Meeting records | FK company (CASCADE), contact/opportunity (SET NULL); CHECK duration > 0 |
| `suppression_records` | Do-not-contact list | UNIQUE `email_sha256`, UNIQUE `domain`; CHECK at least one target |
| `audit_events` | Append-only accountability log | index (entity_type, entity_id), index occurred_at |

Constraint names follow a naming convention (`ck_<table>_<name>`, `fk_<table>_<col>_<ref>`,
…), which keeps migrations reproducible and SQLite batch migrations working.

## Keys, relationships and cascades
* **Primary keys** are surrogate integers. Company names are *not* identifiers, because two
  companies can share a name. The normalized domain is the strongest natural key and is
  unique when present.
* **Foreign keys** are enforced on SQLite too (`PRAGMA foreign_keys=ON` on every connection).
* **CASCADE** from `companies` exists for genuine erasure. Normal operation **archives**
  companies (`archived_at`) instead of deleting them.
* **SET NULL** on contact references keeps commercial history when a contact is deleted.
* **RESTRICT** from facts to sources means a source cannot disappear while facts depend on it.

## Timestamps
`UTCDateTime` stores timezone-aware UTC values. PostgreSQL uses `TIMESTAMP WITH TIME ZONE`.
SQLite stores naive UTC, and the type re-attaches UTC on read. Naive datetimes are rejected
on write, so local time can never slip in.

## Transactions
`session_scope()` commits on success and rolls back on any exception. Services never commit
themselves, which keeps multi-step use cases atomic.

## Migrations: everyday commands (PowerShell)
```powershell
uv run alembic upgrade head                                   # apply
uv run alembic revision --autogenerate -m "add x column"      # after editing models.py
uv run alembic downgrade -1                                   # roll back one step
uv run alembic upgrade head --sql > schema.sql                # offline SQL for review
```
Always read autogenerated scripts before committing them. The test
`test_migrations_create_all_tables_and_match_models` fails if models and migrations diverge.

## SQLite vs PostgreSQL
SQLite needs no server and suits a single-user demo. PostgreSQL is recommended in production
for concurrent writers, row-level locking, robust backups, `timestamptz` and roles. Switch
with `DATABASE_URL=postgresql+psycopg://user:password@host:5432/cyberlead360`. The
PostgreSQL DDL was generated offline from the migrations (`--sql`) during development, but
the full test suite was run on SQLite only.
